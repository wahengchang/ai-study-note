# #219 Persistence 交付紀錄

## 交付

- 新增 `core/persistence/` 同步 public contract、固定去敏 failure、canonical bytes/digest 驗證、私有 `node:sqlite` adapter、migration runner 與 immutable Revision store。
- 新增 `db/migrations/0001-create-persistence-storage.sql` 與 `0002-add-persistence-query-indexes.sql`：append-only ledger、schema version、Revision、producer lineage、FK、immutable trigger 與查詢索引。
- 新增 `apps/cli/db-migrate.ts`／`apps/cli/index.ts`，並只在 `package.json` 加入 `db:migrate` script。
- 新增 file-backed SQLite migration、Revision、atomicity／failure、CLI contract tests。
- GitHub #219 已加入 `ready-for-agent`；新增未標記 ready 的外部 Authoring API 規劃 #241，body 明列 `Blocked by #228`。

## 關鍵決策

- Persistence 對外只透過 `core/persistence/index.ts`；SQLite driver、SQL 與 raw driver failure 不跨 owner 外露。
- canonical bytes 一律由 caller 提供並驗證，不在 Persistence 重新產生 content；寫入與讀取的 `Uint8Array` 皆 copy，避免 caller mutation 改變 evidence。
- migration 只接受 shipped source set，已存在資料庫的 marker、ledger、digest prefix 與 `user_version` 必須完全一致；forward migrations 在單一 `BEGIN IMMEDIATE` transaction 中完成。
- `openPersistence` 不自動 migration；schema version／Revision 無 public update/delete，SQL trigger 另防 private/migration future mutation。

## 審查後修正

- CLI stderr contract：`node:sqlite` 在 Node 24 會把 `ExperimentalWarning` 寫進 stderr，導致 `npm run db:migrate` 的實際輸出被 driver 噪音汙染，三個 CLI contract test 的 exact-stderr 斷言也只在環境帶 `NODE_NO_WARNINGS` 時才通過。`db:migrate` script 與 test 的 spawn 改用 `--disable-warning=ExperimentalWarning`，clean checkout 不再依賴外部環境變數。
- Adapter PRAGMA：移除 `defensive`、`dqs_dml`、`dqs_ddl`。三者是 `sqlite3_db_config()` flag 而非 PRAGMA，SQLite 會靜默忽略（實測讀回 `undefined`），只會造成安全假象；`foreign_keys`、`trusted_schema` 為真實 PRAGMA 並保留。
- 空資料庫判定：`readState` 原本只計 `type IN ('table','trigger','index')`，只含 view 的外部資料庫會被判為空並被寫入，違反「unknown DB 完全不改動」。改為計算所有非 `sqlite_%` 的 `sqlite_master` 物件，並補上 view-only 的 regression test。
- 測試補強：digest／canonical 失敗後加驗 `getRevision` 仍為 `REVISION_NOT_FOUND`，實證失敗不寫入 canonical state；CLI 參數測試改用「合法 path + 未知選項」，讓「開啟資料庫前先驗參數」不再是空斷言。
